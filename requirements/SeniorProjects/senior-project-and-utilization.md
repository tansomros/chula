## 1. เป้าหมายและบริบท (Goal & Context)

ภายในระบบ **CU-PFIS (ระบบสารสนเทศคณะเภสัชศาสตร์ จุฬาลงกรณ์มหาวิทยาลัย / Chula Pharmacy Faculty Information System)** เมนู **"4.2 ฝ่ายวิชาการ >> Senior Project"** แบ่งออกเป็น 2 ส่วนสำคัญที่เชื่อมโยงกันและเชื่อมกับ **CV นิสิต**:
1. **ส่วนที่ 1: เล่มโครงการปริญญานิพนธ์ (`SeniorProject` & `AbstractCompilation`)**
   - จัดเก็บข้อมูลโครงงานรายบุคคลหรือรายกลุ่ม (ปีการศึกษา, รหัสนิสิต, ชื่อ-นามสกุลนิสิต, อาจารย์ที่ปรึกษาโครงการ, ชื่อโครงการภาษาไทยและภาษาอังกฤษ)
   - เจ้าหน้าที่อัปโหลด **ไฟล์ `.pdf` เล่มโครงการฉบับจริง** เก็บไว้ในระบบ (คณะต้องการเก็บเป็นไฟล์จริง ไม่ใช้ลิงก์ Google Drive) พร้อมปุ่ม **`publish`** เพื่อระบุว่าโครงการใดเผยแพร่ได้หรือไม่ได้ (✓ / ✗)
   - มีฟังก์ชันดึง **"หน้า Abstract" (หน้าที่ 3 ของไฟล์ PDF ทุกเล่ม)** ในปีการศึกษานั้น (เช่น 60 ไฟล์ในปีการศึกษา 2569) มารวมกันเป็น **เล่ม Abstract รายงานประจำปีการศึกษา** ให้ดาวน์โหลด/Export เป็น `.pdf` ได้
2. **ส่วนที่ 2: การนำไปใช้ประโยชน์ (`ProjectUtilization`)**
   - ให้อาจารย์ที่ปรึกษาโครงการเข้ามากรอกข้อมูลการนำโครงการไปใช้ประโยชน์ในระบบ `CU-PFIS` (อิง Template จาก Google Form เดิม)
   - อาจารย์จะเห็นเฉพาะโครงการที่ตนเองเป็นที่ปรึกษาเท่านั้น ส่วนเจ้าหน้าที่เห็นข้อมูลทั้งหมด
   - มีระบบส่งอีเมลแจ้งเตือนอาจารย์ที่ปรึกษาเมื่อผ่านไปแล้ว **1 ปี** (แจ้งเตือน **ปีละ 1 ครั้ง**) หากอาจารย์กรอกแล้วให้หยุดแจ้งเตือนทันที หรือหากระยะเวลาปีการศึกษานานกว่า **3 ปี** ไม่ต้องถามอีก (ถือว่าไม่ได้ใช้ประโยชน์)

## 2. ขอบเขต (Scope)

### สิ่งที่ต้องทำในรอบนี้ (In scope)

- จัดการข้อมูลโครงงานปริญญานิพนธ์ (`SeniorProject`) รายบุคคลและรายกลุ่ม เชื่อมโยงนิสิต (`SeniorProjectMember`) และอาจารย์ที่ปรึกษาโครงการ (`SeniorProjectAdvisor`) เข้ากับ `StudentCv`
- ระบบอัปโหลดและจัดเก็บไฟล์ `.pdf` เล่มโครงการฉบับจริง พร้อมตรวจสอบความถูกต้องของไฟล์ (MIME type, ขนาดไฟล์, การเข้ารหัส, จำนวนหน้า) และบันทึก Metadata (`SeniorProjectFile`)
- ปุ่ม/สถานะ **`IsPublished` (`publish`)** สำหรับให้เจ้าหน้าที่กำหนดว่าโครงการใดเผยแพร่ได้หรือไม่ได้ (เครื่องหมายถูก ✓ / ผิด ✗)
- ฟังก์ชัน **รวมเล่ม Abstract ประจำปีการศึกษา (`AbstractCompilation`)**:
  - เลือกปีการศึกษา → ดึงหน้าที่ 3 (Abstract) ของไฟล์ PDF ทุกโครงการในปีการศึกษานั้น (พร้อมรองรับการตรวจสอบ/แจ้งเตือนกรณีไฟล์ใดมีน้อยกว่า 3 หน้าหรืออ่านไม่ได้) → รวมเป็นไฟล์ PDF เล่ม Abstract ประจำปีการศึกษาสำหรับดาวน์โหลด
- ระบบบันทึก **การนำไปใช้ประโยชน์ของโครงการ (`ProjectUtilization`)**:
  - ฟอร์มให้อาจารย์ที่ปรึกษากรอกข้อมูลการนำไปใช้ประโยชน์
  - แสดงเครื่องหมายติ๊กถูก (✓) ในตารางเมื่ออาจารย์กรอกแล้ว โดยเจ้าหน้าที่สามารถคลิกเข้าไปดูรายละเอียดสิ่งที่กรอกได้
- ระบบ **Background Job / Scheduled Notification** แจ้งเตือนการนำไปใช้ประโยชน์:
  - เริ่มส่งแจ้งเตือนเมื่อผ่านไปแล้ว 1 ปี
  - ส่งแจ้งเตือนปีละ 1 ครั้ง
  - หยุดส่งเมื่ออาจารย์กรอกข้อมูลแล้ว หรือเมื่อระยะเวลาปีการศึกษานานเกิน 3 ปี
- ค้นหา (`Search`) และเรียงลำดับ (`Sort`) ตามปีการศึกษา, รหัสนิสิต, ชื่อ-นามสกุลนิสิต, อาจารย์ที่ปรึกษาโครงการ, ชื่อโครงการ (Keyword) และส่งออกรายงาน (`Word`, `PDF`, `Excel`)

### สิ่งที่ไม่รวมในรอบนี้ (Out of scope)

- การจัดเก็บเฉพาะลิงก์ Google Drive แทนไฟล์จริง (ลูกค้ากำหนดชัดเจนในหน้า 8 ว่าต้องการเก็บเป็นไฟล์ `.pdf` ในระบบ ไม่เอาลิงก์ไดร์ฟ)

## 3. ศัพท์ที่เกี่ยวข้อง (Domain terms)

- **`SeniorProject` (โครงการปริญญานิพนธ์ / Senior Project):** โครงงานวิจัยของนิสิตรายบุคคลหรือรายกลุ่ม
- **`SeniorProjectFile` (ไฟล์เล่มโครงการปริญญานิพนธ์):** ไฟล์ PDF ฉบับเต็มของเล่มโครงงานที่เจ้าหน้าที่อัปโหลดเข้าระบบ
- **`IsPublished` (`publish`):** สถานะระบุว่าโครงการอนุญาตให้เผยแพร่ได้หรือไม่ (✓ / ✗)
- **`AbstractCompilation` (เล่มรวมบทคัดย่อประจำปีการศึกษา):** ไฟล์ PDF ที่เกิดจากการดึงหน้า Abstract (หน้าที่ 3) ของทุกโครงงานในปีการศึกษานั้นมารวมเป็นเล่มเดียวกัน
- **`ProjectUtilization` (การนำไปใช้ประโยชน์):** ข้อมูลการนำผลงานโครงงานปริญญานิพนธ์ไปใช้ประโยชน์ ซึ่งกรอกโดยอาจารย์ที่ปรึกษาโครงการ

## 5. ความสัมพันธ์กับข้อมูลอื่นและการเชื่อมต่อภายนอก (Relationships & External Sync)

- เป็น **Single Source of Truth** ของชื่อโครงการ (TH/EN) และอาจารย์ที่ปรึกษาโครงการ เพื่อนำไปแสดงใน `StudentCv` (หัวข้อที่ 3 และ 7) ป้องกันปัญหาข้อมูลขัดแย้งกันระหว่างสองเมนู
- ผูกกับ `FacultyMember` เพื่อกำหนดสิทธิ์ให้อาจารย์เห็นเฉพาะโครงการที่ตนเองเป็นที่ปรึกษา และใช้ส่งอีเมลแจ้งเตือนรายปี

## 6. กติกาทางธุรกิจและลำดับสถานะ (Business Rules & Workflow States)

1. **สิทธิ์การเข้าถึงเล่มโครงการและการนำไปใช้ประโยชน์ (ตามเอกสารหน้า 7–8 และหน้า 12):**
   - ไฟล์เล่มโครงการ (`.pdf`) และการกดปุ่ม `publish`: เจ้าหน้าที่เป็นผู้อัปโหลดและเข้าถึงได้เท่านั้น (`รอยืนยัน Q10`)
   - การนำไปใช้ประโยชน์: User อาจารย์เห็นและกรอกได้เฉพาะโครงการที่ตนเองเป็นที่ปรึกษาเท่านั้น / User เจ้าหน้าที่เห็นข้อมูลทั้งหมดและคลิกเครื่องหมายติ๊กถูกเพื่อดูรายละเอียดที่อาจารย์กรอกได้
2. **การรวมเล่ม Abstract ประจำปี (`AbstractCompilation`):**
   - เมื่อเจ้าหน้าที่เลือกปีการศึกษาและสั่งรวมเล่ม Abstract ระบบจะดึงหน้าที่ 3 (หรือหน้าที่กำหนด) ของไฟล์ `.pdf` ทุกโครงการในปีการศึกษานั้นมารวมกันเป็นไฟล์ `.pdf` เล่มเดียว
   - หากมีไฟล์ใดที่มีจำนวนหน้าน้อยกว่า 3 หน้า หรือไฟล์เข้ารหัส/อ่านไม่ได้ ระบบต้องไม่ล่ม แต่ต้องแสดงรายการไฟล์ที่มีปัญหาให้เจ้าหน้าที่ทราบอย่างชัดเจน
3. **กติกาการส่งแจ้งเตือนการนำไปใช้ประโยชน์ (`ProjectUtilization`):**
   - เริ่มส่งแจ้งเตือนให้อาจารย์ที่ปรึกษาโครงการเข้ามากรอกเมื่อผ่านไปแล้ว **1 ปี** (`รอยืนยันวันอ้างอิงใน Q12`)
   - ส่งแจ้งเตือน **ปีละ 1 ครั้ง**
   - หากอาจารย์กรอกข้อมูลแล้ว **ไม่ต้องส่งถามอีก** (`UtilizationStatus = Submitted`)
   - หากระยะเวลาปีการศึกษานานกว่า **3 ปี** **ไม่ต้องส่งถามอีก** และบันทึกสถานะว่าไม่ได้ใช้ประโยชน์ (`UtilizationStatus = ExpiredNoUtilization`)

## 9. หน้าจอและการส่งออกรายงาน (UI / Frontend & Exports)

- `list` — ตารางแสดงปีการศึกษา, รหัสนิสิต, ชื่อ-นามสกุลนิสิต, อาจารย์ที่ปรึกษาโครงการ, ชื่อโครงการ (ไทย/อังกฤษ), ลิงก์ไฟล์ `.pdf` (เฉพาะเจ้าหน้าที่), สถานะ `publish` (✓/✗), และสถานะการนำไปใช้ประโยชน์ (✓ เมื่อกรอกแล้ว คลิกดูรายละเอียดได้เฉพาะเจ้าหน้าที่) พร้อมปุ่ม **"รวมเล่ม Abstract ประจำปี"**
- `create` / `edit/[id]` — ฟอร์มสร้าง/แก้ไขข้อมูลโครงการ เลือกนิสิตและอาจารย์ที่ปรึกษา อัปโหลดไฟล์ `.pdf` และตั้งค่า `publish`
- `view/[id]` — ดูรายละเอียดโครงการและฟอร์มบันทึกการนำไปใช้ประโยชน์ (สำหรับอาจารย์ที่ปรึกษาและเจ้าหน้าที่)
- การส่งออก: ดาวน์โหลดไฟล์เล่ม Abstract ประจำปี (`.pdf`) และส่งออกรายงานข้อมูลโครงการ (`Word`, `PDF`, `Excel`)

- [ ] เมื่อเจ้าหน้าที่สร้างโครงการปริญญานิพนธ์และผูกกับนิสิต ชื่อโครงการ (ไทย/อังกฤษ) และอาจารย์ที่ปรึกษาโครงการจะเชื่อมโยงกับ CV นิสิตโดยตรง
- [ ] เมื่อเจ้าหน้าที่อัปโหลดไฟล์ `.pdf` เล่มโครงการ ระบบจะจัดเก็บไฟล์จริงพร้อมตรวจจำนวนหน้าและอนุญาตให้เฉพาะเจ้าหน้าที่ดาวน์โหลดไฟล์ได้
- [ ] เมื่อเจ้าหน้าที่กดรวมเล่ม Abstract ของปีการศึกษาที่เลือก ระบบจะดึงหน้าที่ 3 ของทุกไฟล์โครงการในปีนั้นมารวมเป็นไฟล์ `.pdf` เล่มเดียวให้ดาวน์โหลดได้
- [ ] เมื่ออาจารย์ล็อกอินเข้าดูเมนู Senior Project จะเห็นเฉพาะโครงการที่ตนเองเป็นที่ปรึกษาและสามารถกรอกข้อมูลการนำไปใช้ประโยชน์ได้
- [ ] ระบบส่งแจ้งเตือนการนำไปใช้ประโยชน์เมื่อครบ 1 ปี (ปีละ 1 ครั้ง) และหยุดส่งทันทีเมื่ออาจารย์กรอกแล้วหรือเมื่อเกิน 3 ปี

## 11. เคสที่ต้องทดสอบ (Test Cases)

### กรณีสำเร็จ (Happy path)
- สร้างโครงการ → อัปโหลดไฟล์ PDF (ที่มี 3 หน้าขึ้นไป) → สั่งรวมเล่ม Abstract ประจำปีได้ไฟล์ PDF ครบทุกโครงการ → อาจารย์ที่ปรึกษากรอกการใช้ประโยชน์ → ระบบแสดงเครื่องหมาย ✓ และหยุดส่งแจ้งเตือนในปีถัดไป

### กรณีข้อมูลไม่ถูกต้อง / ไฟล์ผิดปกติ
- อัปโหลดไฟล์ที่ไม่ใช่ PDF หรือไฟล์ PDF ที่มีเพียง 2 หน้า → ระบบแจ้งเตือนความผิดปกติและไม่ทำให้การรวมเล่ม Abstract ล่ม

### กรณีอื่น ๆ
- อาจารย์พยายามเข้าดูหรือกรอกการใช้ประโยชน์ของโครงการที่ตนเองไม่ได้เป็นที่ปรึกษา → ระบบปฏิเสธ (`403 Forbidden`)
- โครงการที่ผ่านไปเกิน 3 ปีแล้วยังไม่มีการกรอกการใช้ประโยชน์ → ระบบปรับสถานะเป็นไม่ได้ใช้ประโยชน์และไม่ส่งอีเมลแจ้งเตือนอีก
