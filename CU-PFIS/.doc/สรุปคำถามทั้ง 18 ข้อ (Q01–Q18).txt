สรุปคำถามทั้ง 18 ข้อ (Q01–Q18) จาก roadmap.md แบ่งเป็นข้อสั้นๆ เพื่อให้ตอบไล่ทีละข้อได้ง่ายครับ:

Q01 — ลำดับการส่งมอบ (Release Phasing): โมดูลไหนสำคัญที่สุดต้องส่งมอบใน Phase 1 ก่อน และโมดูลไหนสามารถทยอยทำในเฟสถัดไปได้
Q02 — การแบ่งขอบเขตข้อมูลกับ CUPPEP (CUPPEP Data Ownership): ฟิลด์ไหนให้กรอก/แก้ไขใน CUPPEP vs ระบบใหม่ (CU-PFIS), ต้องพัฒนาหน้าจอเพิ่มใน CUPPEP ส่วนใดบ้าง และถ้าข้อมูลชนกันจะจัดการอย่างไร
Q03 — สิทธิ์ผู้ใช้งาน (Roles & Access): สิทธิ์ของ "เจ้าหน้าที่" ต้องแยกตามภาควิชา/ฝ่ายหรือไม่ และ "นิสิต/ศิษย์เก่า" จะล็อกอินเข้า CU-PFIS โดยตรง หรือใช้งานผ่าน CUPPEP เท่านั้น
Q04 — ช่องทางกรอกข้อมูลการอบรม (Training Input Channel): ยืนยันเลือก แนวทาง B (อาจารย์กรอกตรงในระบบใหม่) เลยหรือไม่ หรือยังต้องรองรับ แนวทาง A (Google Form/Sheet) ควบคู่ในช่วงเปลี่ยนผ่าน
Q05 — ขั้นตอนการอบรมและจังหวะตัดงบ (Training Workflow & Budget Timing): จังหวะที่แน่นอนของสถานะ เจ้าหน้าที่ตรวจสอบแล้ว, คณบดีลงนาม/อนุมัติแล้ว, จองงบ (Reserve), ตัดงบจริง (Consume), ขึ้นแสดงใน CV อาจารย์ รวมถึงเงื่อนไขกรณียกเลิก/คืนงบ/ขอใช้งบเกินวงเงิน
Q06 — รอบปีงบประมาณและการทบยอด (Budget Year & Carryover): วงเงิน 10,000 บาท/คน/ปี นับตาม ปีงบประมาณ, ปีการศึกษา หรือ ปีปฏิทิน? ทบยอดไปปีถัดไปได้ไหม? และมีแหล่งงบอื่นเพิ่มเติมหรือไม่
Q07 — ข้อมูลการได้งานทำรอบ Final จากจุฬาฯ (Chula Final Employment Data): ไฟล์ข้อมูลจากจุฬาฯ มาในรูปแบบใด/ช่องทางใด ใช้คีย์อะไรจับคู่นิสิต และหากบางฟิลด์ว่างหรือขัดแย้งกับรอบคณะจะยึดเงื่อนไขไหน
Q08 — เกณฑ์ตรวจผลงานนิสิตและหลักฐานใบประกอบฯ (Student Achievements & License Proof): เกณฑ์คัดกรองผลงานที่จะขึ้น CV, รายละเอียดฟิลด์ทุน/เงินสนับสนุนที่ต้องกรอก และต้องแนบไฟล์หลักฐานอะไรบ้างสำหรับผลงานนิสิตและผลสอบใบประกอบฯ
Q09 — สูตรคำนวณร้อยละการสอบผ่านใบประกอบฯ (License Pass Rate Formula): ตัวหารที่ใช้คิดเปอร์เซ็นต์คือจำนวนใด (จำนวนรับเข้า / จำนวนผู้สำเร็จการศึกษา / จำนวนผู้เข้าสอบจริง) และกรณีนับการสอบซ้ำ (retake) นับอย่างไร
Q10 — ความหมายของปุ่ม "Publish (เผยแพร่)" ใน Senior Project: โครงงานที่กด Publish แล้ว ใครบ้างที่ดูหรือดาวน์โหลดไฟล์ PDF ได้ (เฉพาะเจ้าหน้าที่ / อาจารย์และนิสิต / บุคคลภายนอก)
Q11 — กฎการดึง Abstract หน้าที่ 3 (Abstract Page 3 Rule): หน้า Abstract อยู่หน้าที่ 3 เป๊ะทุกเล่มทุกปีการศึกษาหรือไม่ และเล่มรวม Abstract ประจำปีต้องมีหน้าปก สารบัญ หรือรันเลขหน้าใหม่ด้วยไหม
Q12 — เงื่อนไขแจ้งเตือนการนำไปใช้ประโยชน์โครงงาน (Utilization Reminder Timeline): เริ่มนับ "ครบ 1 ปี" จากวันที่อ้างอิงไหน, ถ้าอาจารย์กรอกแล้ว 1 ครั้งหยุดแจ้งเตือนถาวรเลยไหม และหากอาจารย์ที่ปรึกษาย้าย/เกษียณจะส่งแจ้งเตือนไปที่ใคร
Q13 — ข้อมูลย้อนหลัง 10 ปี (10-Year Historical Data): ปัจจุบันข้อมูลย้อนหลัง 10 ปีเก็บอยู่ที่ไหน รูปแบบและปริมาณเท่าไหร่ และใครเป็นผู้ตรวจยืนยันความถูกต้องหลังนำเข้า
Q14 — ตัวชี้วัด Dashboard และแม่แบบรายงาน (Dashboard KPIs & Report Templates): รายการ KPI สูตรคำนวณ ตัวกรอง และ Template ไฟล์ Word/PDF/Excel ที่ต้องใช้ในการตรวจรับมีอะไรบ้าง
Q15 — ขอบเขตระบบ 2 ภาษา (Bilingual Scope TH/EN): รองรับ 2 ภาษาเฉพาะป้ายชื่อ/เมนู UI หรือรวมถึงฟิลด์ข้อมูลทุกตัว, ไฟล์ Export (CV/รายงาน), Template และอีเมลแจ้งเตือนด้วย
Q16 — การเชื่อมต่อ Scopus (Scopus Integration): ต้องการเชื่อมต่อ Scopus API อัตโนมัติ (และคณะมี API Key/สิทธิ์ใช้งานอยู่แล้วหรือไม่) หรือใช้วิธีนำเข้าไฟล์/กรอกข้อมูลเอง
Q17 — ข้อกำหนดเชิงเทคนิคและขนาดระบบ (Non-Functional & Sizing): จำนวนผู้ใช้งานพร้อมกันโดยประมาณ, ขนาดไฟล์ PDF ต่อปี, นโยบาย Backup/เก็บรักษาข้อมูล และสภาพแวดล้อม Hosting/ระบบล็อกอิน (SSO)
Q18 — PDPA และข้อมูลอ่อนไหว (PDPA & Sensitive Fields): นโยบายระยะเวลาจัดเก็บ สิทธิ์การเข้าถึง และการ Export สำหรับ เลขบัญชีธนาคารอาจารย์ และ ข้อมูลผลประเมินผู้ใช้บัณฑิต

คำตอบทั้ง 18 ข้อ (Q01–Q18) ตอบเป็น A01-A18 ตามลำดับข้อ

A01 - ในการส่งมอบ Phase 1 จะต้องได้ โครงสร้างและ UX/UI ของหน้า Frontend เว็บไซต์  และโมดูลที่สำคัญต้องสามารถใช้ได้เลยคือ CV อาจารย์ และ นิสิต ส่วนโมดูลอื่นที่จะต้องทยอยทำต่อคือ การอบรม และโมดูลอื่นๆที่เหลือ
A02 - ข้อมูลนิสิตตอนนี้คิดว่าจะต้องให้ นิสิตกรอกข้อมูลตัวเองทั้งหมดที่ CUPPEP แล้วดึงข้อมูลส่งมาแสดงที่ ระบบใหม่ ดังนั้นหน้าจอ input ข้อมูล CV หรือผลงาน ต่างๆ ให้สร้างหน้าจอเพิ่มที่ CUPPEP ก็จะหลีกเลี่ยงการชนกันของข้อมูลได้
A03 - สิทธิ์ของ  "เจ้าหน้าที่" ต้องแยกตามภาควิชา/ฝ่าย  และ "นิสิต/ศิษย์เก่า" ตอนนี้ยังไม่มีภาพที่จะต้องล็อกอินเข้า CU-PFIS ยังคงให้ใช้งานผ่าน CUPPEP เท่านั้นก่อน
A04 - ช่องทางกรอกข้อมูลการอบรม (Training Input Channel): ยืนยันเลือก แนวทาง B (อาจารย์กรอกตรงในระบบใหม่) แต่อาจจะต้องเพิ่มแนวทางในการ import ข้อมูลเก่าๆ จาก excel เข้าระบบด้วย เพื่อทำการ data migrate
A05 - การตัดงบจะต้องตัดหลังจากที่ คณบดีลงนาม/อนุมัติแล้ว  เพราะถ้ายังไม่อนุมัติยังมีสิทธิ์ที่จะทำการยกเลิกการอบรมนั้น หรือ ยกเลิกจองงบนั้นอยู่
A06 - วงเงิน 10,000 บาท/ปี/คน (กรอกระบุได้) นับตามปีงบประมาณ 1 ต.ค.69 - 30 ก.ย.70  ตั้งยอดใหม่ทุกปี  และมีเงื่อนไขเพิ่มเติมว่า อ.สามารถยืมโควต้าเงินอบรมในอนาคตของตัวเอง ได้ค่ะ เช่น ปีงบ 70 นี้ (1 ต.ค.69 - 30 ก.ย.70) อ.A ใช้หมด 10,000 บาท และขอยืมเงินอนาคตตัวเองไปอบรมเพิ่มอีก 5,000 บาท ดังนั้น ในปีงบ 71 (1 ต.ค.70 - 30 ก.ย.71)  อ.A จะเหลือเงินโควต้า 5,000 บาท
A07 - ข้อมูลการได้งานทำที่ได้จากจุฬา จนท.จะได้จากไหนไม่ต้องสนใจ แต่เขาจะต้องเอามา recheck เองด้วยตา เทียบกับข้อมูลของเราที่ดึงจาก CU-PPEP ไปแสดงที่หน้าจอ ระบบใหม่ และ จทน. สามารถกรอก/แก้ไขข้อมูลที่ยืนยันแล้วในระบบใหม่ได้ ให้ขึ้นอยู่กับ จนท. ตัดสิน/ยืนยัน  ส่วนข้อมูลที่ยืนยันแล้วจะส่งกลับไปให้ CU-PPEP หรือไม่อันนี้ขอติดไว้ก่อนค่อยวางแผนต่อไป
A08 - ไม่ต้องแนบไฟล์ใบเกียรติบัตร หรือใบประกอบฯ อะไร ในระบบ แค่เพียงทำรายการการสอบหรือใบประกอบฯ ต่างๆ ไว้ให้นิสิตเลือกยืนยันด้วยตนเองว่าได้รับ หรือ ผ่านอะไรบ้างแล้ว เท่านั้น
A09 - เบื้องต้นใช้ จำนวนผู้สำเร็จการศึกษา เป็นคิด % ก่อน  กรณีนับการสอบซ้ำ ยังไม่เห็นในต้นฉบับ Requirement ของลูกค้านะ
A10 - เฉพาะ จนท. อาจารย์ และนิสิต เท่านั้น ที่สามารถสืบค้นและดูได้ 
A11 - รูปแบบการเรียงหน้า abstract ของแต่ละเล่มอาจจะไม่ตรงกันเสมอไป แต่มี keyword ที่ตรงกันคือ "Abstract" ที่อยู่บรรทัดแรก และจัดกึ่งกลางหน้า และอาจจะอยู่ระหว่างหน้า 3-5 แบบนี้พอจะจับ ได้ไหม  ส่วนรูปเล่มที่รวบรวม จะมีหน้าแรกเป็นหน้าปก แค่นั้น หน้าต่อไปจะเป็น หน้า Abstract ของแต่ละเล่มไปเรื่อยๆ
A12 -  เริ่มนับ "ครบ 1 ปี" จากวันที่ตีพิมพ์ แต่ถ้าเป็นผลงานเก่าๆที่ผ่านมาหลายปีแล้ว จะสร้างฟังก์ชันให้ จนท. กดแจ้งเตือนเอง และจากนั้นให้นับ จากวันที่แจ้งเตือนครั้งล่าสุด และจะแจ้งเตือน 3 ปี/3 ครั้ง แล้วไม่เตือนอีก หาก อ.ไม่เข้ามากรอกเลย   และหาก อ. เข้ามากรอกแล้วไม่ต้องส่งแจ้งเตือนอีกเลย
A13 - เก็บเป็นกระดาษ หรือ เก็บไว้ที่เว็บไซต์อื่นๆ ที่ให้บริการฟรี คนที่จะนำเข้าหรือตรวจสอบจะเป็น จนท. แบบ manual 
A14 - จะกำหนดภายหลังได้ข้อสรุปในการประชุมครั้งหน้า
A15 - รองรับ 2 ภาษา ทั้งหมด รวมข้อมูลใน database บางอย่างที่สำคัญด้วยต้องเก็บทั้ง ไทยและอังกฤษ รวมทั้ง E-mail ที่แจ้งเตือนด้วย
A16 - การเชื่อมต่อข้อมูล Scopus อันนี้ผมเองยังไม่มีความรู้ว่าต้องใช้ api อะไรหรือไม่อย่างไร แต่ลูกค้าแค่เปิดหน้าเว็บข้อมูลให้ดูว่าอยากได้ข้อมูล CV ของ อ. ในคณะที่อยู่ใน Scopus มาไว้ที่ระบบใหม่ด้วย
A17 - จำนวนผู้ใช้งานพร้อมกันโดยประมาณ น่าจะไม่เกิน 10 คน , ขนาดไฟล์ PDF คาดเดาไม่ได้ แต่เราขนาดพื้นที่ Hosting สำหรับเก็บข้อมูลเพียงพออยู่ หากไม่เพียงพอสามารถขยายเพิ่มได้ และเรียกเก็บเงินจากลูกค้าได้ 
A18 - ในระบบจะต้องมี หน้าที่ให้ กดยอมรับเรื่อง PDPA ก่อนเข้าใช้งานระบบในครั้งแรก เพิ่มเก็บว่าได้ยืนยันให้ระบบเก็บข้อมูลส่วนบุคคล
