## 3. ขอบเขตระบบใหม่กับ CUPPEP

ระบบใหม่ดูแลหลักไม่ได้แปลว่าต้องย้ายทุกหน้ากรอกจาก CUPPEP หรือรับข้อมูลใหม่มาทับได้อัตโนมัติ

| ข้อมูล | แหล่งตาม scope | หน้าที่ระบบใหม่ | ขอบเขต CUPPEP ที่ต้องตกลง |
|---|---|---|---|
| ทั่วไป/ที่ปรึกษา/การศึกษา/ฝึกงาน | CUPPEP | รับและเชื่อม CV | ตรวจฟิลด์และความพร้อมข้อมูลเดิม |
| รอบสมัคร/ชื่อโครงการ | อาจเพิ่มใน CUPPEP | ดูแลและแสดง CV | ทางเลือกจุดกรอกยังไม่ยุติ |
| ผลงานนิสิต | เสนอกรอก CUPPEP | ตรวจ ขอแก้ไข รับรอง แสดง CV | เมนูเพิ่มใหม่ สถานะและความเห็นส่งกลับ |
| งานทำครั้งแรก | เสนอ CUPPEP แทน Form คณะ | เทียบ/ปรับตาม Final จุฬาฯ | ฟิลด์และหน้ากรอกที่เพิ่ม |
| ใบประกอบ | CUPPEP กรอกเอง | รวมและแสดงสถิติ | เมนูเพิ่มใหม่และรายละเอียดตรวจรับ |
| อบรม | Form/Sheet หรือระบบใหม่ | ตรวจ เอกสาร อนุมัติ งบ CV | ล็อกอินแบบ CUPPEP ไม่ใช่ข้อยืนยัน SSO |
| ผู้ใช้บัณฑิต | Google Form/Sheet | จับคู่ ดูแล รายงาน | ไม่ระบุเพิ่มหน้ากรอกใน CUPPEP |
| โครงการ/ใช้ประโยชน์ | เจ้าหน้าที่/อาจารย์ระบบใหม่ | เก็บไฟล์ รายงาน ติดตาม | ยืนยันแหล่งข้อมูลโครงการที่เชื่อม CV |

ข้อเสนอ Tech Lead/BA รอยืนยัน: ข้อมูลขัดแย้งให้เจ้าหน้าที่ตรวจ ไม่ทับข้อมูลที่แก้แล้วโดยอัตโนมัติ พร้อมเก็บที่มาและประวัติ

## 4. กระบวนการสำคัญ

### 4.1 อบรม

- แยกขั้น “ตรวจถูกต้อง” จาก “แจ้งอนุมัติหลังคณบดีลงนาม”
- A: กรอก Form → ติ๊กตรวจใน Sheet → นำเข้าระบบ; ต้องถามขั้นเอกสารและแจ้งอนุมัติ
- B: กรอกระบบ → แจ้งเจ้าหน้าที่ → ขอแก้ไขหรือรับข้อมูลถูกต้อง → ส่ง PDF ให้อาจารย์เสนอบันทึก → ลงนามนอกระบบ → เจ้าหน้าที่แจ้งอนุมัติ
- ระบุเก็บข้อมูลเมื่อกด “ตกลง” และสถานะกำลังดำเนินการ/อนุมัติ แต่ไม่ระบุจุดกันงบ ตัดยอดใช้จริง หรือเข้า CV
- ประเภทคณะจัดและอบรมระยะสั้น/ต่างประเทศระบุไม่ต้องขออนุมัติ อย่าใช้ขั้นอนุมัติเดียวกับสองประเภทแรกโดยอัตโนมัติ
- 10,000 บาท/คน/ปีเป็นค่าที่ระบุใน scope ต้องยืนยันการตั้งค่ารายปีและเงื่อนไข ไม่ถือว่าคงที่ถาวร

### 4.2 ผลงานนิสิต

CUPPEP รับข้อมูล → ระบบใหม่รับให้ตรวจ → ขอแก้ไขหรือรับรอง → แสดง CV
ต้องตกลงที่เก็บรายการรอตรวจ การส่งความเห็นกลับ และใครแก้หลังรับรองได้

### 4.3 งานทำ

รับครั้งแรกจาก CUPPEP → รับ Final จุฬาฯ → จับคู่ → เจ้าหน้าที่เทียบ/ปรับ → บันทึกตรวจแล้ว
ต้องยืนยันการเก็บต้นฉบับสองแหล่ง และป้องกันการนำเข้ารอบถัดไปทำลายผลตรวจล่าสุด

### 4.4 โครงการ/Abstract

ข้อมูลโครงการ สมาชิก ที่ปรึกษา → อัปโหลด PDF → กำหนดเผยแพร่ → เลือกปีและรวม Abstract → ตรวจผลและส่งออก
ต้องถามหน้าที่ 3 เป็นลำดับหน้า PDF หรือเลขพิมพ์ และจัดการไฟล์สั้น เสีย เข้ารหัส หรือรูปแบบต่างปีอย่างไร
“เผยแพร่” ยังไม่แปลว่าเปิดสาธารณะ เพราะเอกสารจำกัดไฟล์เฉพาะเจ้าหน้าที่

## 6. ความเสี่ยง/ความไม่ชัดเจน

- เมนูอบรมระบุเฉพาะเจ้าหน้าที่ แต่อาจารย์ต้องกรอกและตารางสรุปมีแสดงรายบุคคล ต้องแยกหน้ากรอกกับหน้าบริหาร
- CV กับข้อมูลโครงการอ้างถึงกัน ต้องกำหนดแหล่งแก้หลักระดับฟิลด์ ป้องกันข้อมูลวนหรือไม่ตรงกัน
- Sheet ที่มีแก้/ลบแถวต้องมีตัวระบุและกติกาตรวจซ้ำ ไม่สรุปให้ใช้เลขแถว
- PDF และประวัติย้อนหลังอาจกระทบพื้นที่/สำรอง/เวลานำเข้า แต่ยังไม่มีปริมาณพอประเมิน
- Word/PDF/Excel และ template ปรับได้มีความหมายต่างกัน ต้องขอไฟล์ตัวอย่างก่อนประมาณงาน
- ต้องยืนยันผู้รับผิดชอบแทนเมื่อเจ้าหน้าที่ออกหรือเปลี่ยนที่ปรึกษา และสิทธิ์ศิษย์เก่า
- ยังไม่มีหลักฐาน API หรือรูปแบบเชื่อม CUPPEP/Google/Scopus จึงไม่สรุปวิธีเทคนิค
